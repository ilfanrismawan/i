# Eevee-only shot-by-shot Blender render contract

- Default and required render engine: **Blender Eevee**. Detect supported identifier (`BLENDER_EEVEE_NEXT` or `BLENDER_EEVEE`) from the installed version. Do not silently switch to Cycles. If unavailable, report a blocker and ask for a compatible Blender installation/configuration.
- Inspect render device, samples, shaders and alpha sorting early. Eevee differences from Cycles must be verified with stills and *motion* tests especially for glass, UI fades, transparent layers and cutaways. Use non-destructive local material adapters, not source asset replacement.
- **No overlays baked into Blender output**: no subtitles, explanatory text, arrows, charts, counters, labels, logos, watermarks, editor UI, HUD, or debug guides. Hide any legacy instructional TEXT/FONT objects, compositing overlays and UI labels intended as explanatory overlays. *Diegetic* objects genuinely part of the scene (phone app UI or signage central to the explanation) may remain. Meaningful 3D mechanism visualization (electrodes, conceptual field curves) is allowed; decorative overlay graphics are not.
- Shoot independent, numbered shots. ONE shot is rendered, checked, encoded, and handed off to CapCut **as soon as the shot is approved**. Do not render the next shot until CapCut import/edit confirmation in sequential mode; do not wait for all shots to prepare a handoff. Never assume CapCut can be remotely controlled or auto-imported. The handoff contains the clip, status, editable edit guide and optional preview.
- Render PNG image sequence for each shot, then FFmpeg to a separate high-quality CFR MP4 for CapCut. Match 9:16, resolution 1080×1920, 30 fps (unless user explicitly changes). Keep render without burned-in text and without soundtrack; edit/audio added in CapCut.
- Suggested first test: 540×960 at 16/32 Eevee samples. Final default 1080×1920, 32 samples. Raise to 64 only when a motion test shows unacceptable temporal artifacts. Run separate render tests for UI transparency, glass and thin geometry.
- Render one representative still plus short motion window before full-shot output. Ensure frames have expected dimensions, ordering, validity and absence of duplicates/blank frames. Verify entire shot before marking `READY_FOR_CAPCUT`.
- Keep per-shot sequence folders, clip name, original timeline frame range, FPS, source hash and QA status. Resume only matching render settings and assets. Never mix Cycles original frames with Eevee final frames.
- Prefer FFmpeg `-framerate 30` with a validated PNG pattern, `libx264 -crf 16 -preset medium -pix_fmt yuv420p` (or local hardware equivalent if verified). Do not pre-add transitions in FFmpeg; CapCut is responsible for transitions, sound, subtitles, final mix and export.

**v4:** Blender/VSE/compositor and FFmpeg must not concatenate completed shots. CapCut Pro is sole editorial assembly; see `references/capcut-first-workflow.md`.
